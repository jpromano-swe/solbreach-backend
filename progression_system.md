# SolBreach Progression System

# Objective

This document defines user progression mechanics in SolBreach.

The progression system exists to:
- reward learning
- structure advancement
- unlock complexity gradually
- reinforce achievement

---

# Progression Philosophy

Users should feel:
- increasingly capable
- challenged but not overwhelmed
- continuously advancing

Progression is NOT purely cosmetic.

It reflects:
# adversarial capability growth.

---

# Current Progression Structure

## Stage 1 — Vulnerabilities
Learn exploit primitives.

Current MVP scope.

---

## Stage 2 — Research Labs
Guided protocol investigation.

Future implementation.

---

## Stage 3 — Breach Rooms
Advanced adversarial environments.

Future implementation.

---

# Level Unlock Logic

Initial logic:
- users complete levels sequentially

Example:
- Level 0 unlocks Level 1
- Level 1 unlocks Level 2

---

# XP System

Users gain XP for:
- completing levels
- successful submissions
- future achievements

Example values:
- Easy: 100 XP
- Medium: 250 XP
- Hard: 500 XP

XP values should remain configurable.

---

# Certifications

Certifications unlock when:
- milestone requirements are met

Example:
- complete all beginner vulnerability levels

Initial implementation:
- database unlock state only

Future:
- cNFT minting

---

# User Progress Data

Track:
- completed levels
- total XP
- unlocked stages
- certifications
- timestamps

---

# Replay Policy

Users may replay completed levels.

However:
- XP should NOT be infinitely farmable

Initial policy:
- XP awarded once

---

# Future Progression Features

Future systems may include:
- rankings
- streaks
- achievement systems
- researcher tiers
- reputation scoring

NOT required for MVP.

---

# MVP Goal

The MVP progression system should:
- feel rewarding
- unlock naturally
- remain deterministic
- support future expansion
